# 危害分析与 FMEA（ISO 14971）

> 对应 `docs/医疗器材合规优化方向.md` **第五章「风险管理文件」**、**第三梯队第 14 项**。
>
> 本表用 FMEA 形式（失效模式 → 影响 → 现行控制 → 残余风险）覆盖本项目
> **已经识别并处置**的危害，以及**明确接受**的残余危害。
>
> **免责声明**：这是工程层面的危害分析演示，不是 ISO 14971 要求的正式风险管理文档
> （缺风险管理计划、风险可接受准则、生产后信息收集等要素）。

---

## 1. 严重度 / 可能性 / 检出度定义

| 等级 | 严重度 S | 可能性 P | 检出度 D（越低越好检出） |
|------|---------|---------|----------------------|
| 5 | 死亡 | 频繁 | 无法检出 |
| 4 | 严重伤害 | 很可能 | 仅事后可发现 |
| 3 | 中度伤害 | 偶尔 | 需专门检查 |
| 2 | 轻微伤害 | 很少 | 自检可发现 |
| 1 | 无伤害 | 极不可能 | 必然发现 |

**RPN = S × P × D**，本项目把 **RPN ≥ 40** 视为必须控制。

## 2. 危害分析表

### H-1 报警只报一次（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 告警条件持续成立，但只在首次越限时报一次，此后静默 |
| 原因 | 原实现 `highLatched` 锁存，仅在数值回落时解锁 |
| 影响 | 医护以为「已经在报」，实际患者持续恶化无人知晓 → **死亡** |
| S / P / D | 5 / 4 / 4 → **RPN 80** |
| 控制措施 | 改为状态机 + 周期重复提示：`AlarmDetector::updateCondition()` 按 `alarmRepeatMs` 重报；确认后仍会再报；超时未确认自动升级 |
| 验证 | `alarm_state_test` 用例 1、2、3 |
| 残余风险 | 重复间隔过长（默认 5 s）在极端情况下仍可能延迟发现 → 由 `alarmRepeatMs` 可配置，默认值经临床确认前属残余风险 |
| 残余 RPN | 5 / 1 / 2 = **10（可接受）** |

### H-2 传感器脱落 / 信号质量差被当作正常值（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 导联脱落时输出「看起来正常」的数值，不报警 |
| 原因 | 旧实现无信号质量（SQI）概念 |
| 影响 | 低氧 / 停搏被显示为正常 → **死亡** |
| S / P / D | 5 / 4 / 5 → **RPN 100** |
| 控制措施 | `ChannelSample::quality` + `invalid`；`AlarmDetector` 对低 SQI / invalid **抑制生理报警并改发技术报警**；曲线上以灰色虚线 / `--` 呈现 |
| 验证 | `alarm_state_test` 用例 6 |
| 残余风险 | SQI 由模拟器生成，真实设备需传感器侧提供 |
| 残余 RPN | 5 / 2 / 2 = **20（可接受）** |

### H-3 运动伪迹被当作真实异常（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | HR 单帧从 60 跳到 250，被当作真实心动过速报警 |
| 原因 | 无变化率校验 |
| 影响 | 报警疲劳 → 医护关闭报警 / 忽略真报警 → **严重伤害** |
| S / P / D | 4 / 4 / 3 → **RPN 48** |
| 控制措施 | `ChannelSample::artifact`；伪迹样本不参与生理判定，改发技术报警「数据不可信」，伪迹消失后自动清除 |
| 验证 | `alarm_state_test` 用例 9 |
| 残余风险 | 伪迹与真实急变的边界需临床标定 |
| 残余 RPN | 4 / 2 / 2 = **16（可接受）** |

### H-4 数值被静默裁剪而掩盖病情（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | HR 250 被 `clamp()` 裁成量程上限 180 后显示 |
| 原因 | 数据路径误用 `ChannelConfig::clamp()` |
| 影响 | 危重程度被低估 → **严重伤害** |
| S / P / D | 4 / 3 / 3 → **RPN 36** |
| 控制措施 | 数据路径不做裁剪；超量程以 `↑` / `↓` 角标提示；`clamp()` 加 `@warning` 禁止用于告警路径；历史文件 v2 记录原始值与标记 |
| 验证 | `alarm_state_test` 用例 8、9；`compliance_test` 用例 4（artifact 保存） |
| 残余风险 | 曲线可能被极端值压扁 → 需在绘图层做 Y 轴截断（**未实现，见 §4**） |
| 残余 RPN | 2 / 2 / 1 = **4（可接受）** |

### H-5 系统校时导致告警计时错乱（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | NTP 回拨 1 小时后，去抖 / 重复 / 升级计时全部失效 |
| 原因 | 计时使用 `QDateTime`（墙钟） |
| 影响 | 报警永不触发或疯狂重报 → **死亡** |
| S / P / D | 5 / 3 / 4 → **RPN 60** |
| 控制措施 | `monotonicMs`（`QElapsedTimer`）作为唯一计时基准；墙钟只用于显示 |
| 验证 | `alarm_state_test` 用例 10（模拟墙钟回拨 1 小时） |
| 残余 RPN | 5 / 1 / 1 = **5（可接受）** |

### H-6 报警被无限期静音 / 暂停（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 操作者静音后忘记恢复，报警永久无声 |
| 原因 | 旧实现无静音 / 暂停机制（更糟：根本没有声音） |
| 影响 | **死亡** |
| S / P / D | 5 / 4 / 4 → **RPN 80** |
| 控制措施 | 暂停必须有时长（普通 ≤120 s、危急 ≤30 s）；倒计时可见；到期自动恢复；恢复时若仍有未处理告警立即重报；暂停 / 恢复写审计 |
| 验证 | `AlarmBanner` 单元（无 GUI 自动化，依赖目视验证） |
| 残余风险 | 无 GUI 自动化测试覆盖 |
| 残余 RPN | 5 / 2 / 3 = **30（需补充可用性测试）** |

### H-7 历史文件损坏导致回放数据错误（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 文件被截断，解析时静默跳过坏行，回放出的曲线「看起来正常」 |
| 原因 | 旧实现忽略解析失败 |
| 影响 | 复查结论错误 → **中度伤害** |
| S / P / D | 3 / 4 / 4 → **RPN 48** |
| 控制措施 | 按行容错 + `LoadStats` 明确上报坏行数 / 截断字节；全部坏行则判失败；导入前做 SHA-256 校验 |
| 验证 | `compliance_test` 用例 1、2、4 |
| 残余 RPN | 3 / 2 / 1 = **6（可接受）** |

### H-8 越权修改报警限（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 非授权人员把 HR 高限改成 200 bpm，真实心动过速不报警 |
| 原因 | 任何人可改配置，且无审计 |
| 影响 | **死亡** |
| S / P / D | 5 / 3 / 4 → **RPN 60** |
| 控制措施 | 三级角色权限（查看者 / 操作者 / 管理员）；改配置需管理员；业务层二次校验；二次确认弹窗列出「旧值 → 新值」；全部写审计 |
| 验证 | `compliance_test` 用例 3 |
| 残余风险 | 演示环境无密码认证，「切换角色」本身只做审计不阻断 |
| 残余 RPN | 5 / 2 / 3 = **30（需接入真实身份认证）** |

### H-9 单位错配（℃ / ℉）（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 体温通道单位写成 `F` 但数值是 ℃，36.8 被读成 36.8 ℉ |
| 原因 | 无单位校验 |
| 影响 | 误判为严重低体温 → **中度伤害** |
| S / P / D | 3 / 3 / 4 → **RPN 36** |
| 控制措施 | `ChannelConfig::validateUnit()` 三重校验（已知单位 / 量纲族 / 物理可能区间）；配置面板标 ⚠；二次确认弹窗列出单位问题 |
| 验证 | `compliance_test` 用例 5 |
| 残余 RPN | 3 / 1 / 3 = **9（可接受）** |

### H-10 采集线程卡死但界面显示「旧数据」（**部分控制**）

| 项 | 内容 |
|----|------|
| 失效模式 | 采集停止，屏幕上仍是最后一个数值，看起来像「患者稳定」 |
| 原因 | 无心跳监控 |
| 影响 | 医护依据过期数据判断 → **死亡** |
| S / P / D | 5 / 3 / 5 → **RPN 75** |
| 控制措施 | `VitalSignSimulator::heartbeat()` + `MainWindow::onWatchdogTick()`：约 4 s 序号不推进即记录技术报警、写审计、日志告警 |
| 验证 | 无自动化测试（需要注入线程阻塞） → **残余风险** |
| 残余风险 | 看门狗只报警，不做**自动恢复**（重启采集线程）；且数值本身未做「过期灰显」 |
| 残余 RPN | 5 / 2 / 4 = **40（需进一步控制）** |

### H-11 用户信息缺失导致报警归属不明（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 多床监护时无法判断报警属于哪位患者 |
| 影响 | 处置错误患者 → **严重伤害** |
| 控制措施 | `PatientBarWidget` 常驻显示床号 / ID / 姓名 / 患者类型；修改写审计 |
| 验证 | 目视验证 |
| 残余 RPN | 3 / 1 / 2 = **6（可接受）** |

### H-12 模拟数据被误认为真实测量（**已修复**）

| 项 | 内容 |
|----|------|
| 失效模式 | 演示界面上出现「72 bpm」，被误当成真实监护 |
| 影响 | 延误真实患者处置 → **死亡** |
| 控制措施 | 顶部常驻高对比 **「演示模式 · 模拟数据」** 橙色标识；启动日志明确声明；README 声明；数据源全部来自 `VitalSignSimulator` |
| 残余 RPN | 5 / 1 / 3 = **15（可接受）** |
