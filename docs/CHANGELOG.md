## [1.1.1] — 2026-10-19

**主题**：实机运行发现的三个告警键 / 计时缺陷修复（均有回归测试守护）。

> 这三个缺陷都是**跑起来才暴露**的：单元测试全绿，但审计日志里的
> `持续时间=?s` 和 `条件=1/0/LO` 一眼就看得出不对。

### 修复 — 告警持续时长丢失（`AlarmEvent::trackKey`）

- **现象**：审计日志「告警确认」记录出现 `持续时间=?s`；报警列表时长列显示「—」。
- **根因**：技术报警在 `m_tracks` 中的键是 `"1/<通道>/SQI"`，而下游用
  `AlarmEvent::conditionKey()`（生成 `"1/<通道>/HI"`）去 `activeDurationsMs()`
  查表。两者**属于不同键空间**，永远查不到。
- **修复**：`Track` 保存真实键 `key`，`makeEvent()` 回填 `AlarmEvent::trackKey`；
  `MainWindow`（审计）与 `AlarmBanner`（排序 / 时长列）统一改用 `trackKey`。
  同时 `activeDurationsMs()` 不再跳过 `onsetMs == 0` 的记录（返回 0 而非缺失）。
- **回归**：`alarm_state_test` 用例 12（含「conditionKey 不命中技术报警」的反向断言）。

### 修复 — 条件键顺序写反（`类别/通道` vs `通道/类别`）

- **现象**：日志中通道 1 的下限告警记为 `条件=1/0/LO`——形如「通道/类别」。
- **根因**：`detect()` 的 `baseKey` 写作 `.arg(cfg.id).arg(0)`，与
  `AlarmEvent::conditionKey()` 约定的「类别/通道」**顺序相反**。
  于是同一条件在检测器内部与界面/日志侧是两套键，按通道筛选与跨模块比对全部错位。
- **修复**：`baseKey` 改为 `类别/通道`，并注释声明「键是跨模块契约」。
- **回归**：`alarm_state_test` 用例 13（断言 `trackKey == conditionKey()` 且为 `"0/2/HI"`）。

### 修复 — 告警确认非幂等（审计日志被连点淹没）

- **现象**：实机连点「确认」7 次，审计日志写入 21 条重复「告警确认」记录，
  同一批告警被反复记录，真正的事件反而被埋掉。
- **根因**：`AlarmDetector::acknowledge()` 对已确认的告警仍返回事件。
- **修复**：跳过 `t.acknowledged == true` 的记录；确认是**一次性事件**，
  条件仍成立时的重复提示由 `updateCondition()` 的 `repeatMs` 负责，不依赖重复确认。
- **回归**：`alarm_state_test` 用例 12 末尾（「重复确认不产生重复审计记录」）。

### 测试

- `alarm_state_test`：11 → **13 个用例**
- `ctest`：2/2 通过

## [1.1.0] — 2026-10-19

**主题**：补齐 `docs/医疗器材合规优化方向.md` 中全部代码可实现的条目，
并建立第三梯队过程文档。

### 新增 — 报警系统
- 报警优先级语义（`AlarmPriority` 高 / 中 / 低）+ 二级危及生命阈值，
  **移除「超出半个量程 = 严重」的临床无意义折算**
- 报警状态机：`Active → Acknowledged / Cleared / Escalated / LatchedSilent`
- 修复「告警只报一次」：改为持续重复提示（`alarmRepeatMs`）+ 超时升级
- 报警延时改为毫秒制（`alarmDelayMs`），采样率变化行为一致
- 报警暂停（Pause）：危急 ≤30 s / 普通 ≤120 s，倒计时可见，到期自动恢复
- 静音（Mute）与暂停语义分离
- 活动报警列表：按优先级 + 未确认 + 持续时间排序，显示确认状态

### 新增 — 信号质量与数据完整性
- 信号质量指标 SQI（`ChannelSample::quality`），低质量抑制生理报警并改发技术报警
- 运动伪迹标记（`ChannelSample::artifact`），伪迹不参与生理判定
- 移除数据路径的 `clamp()`：越限值原样显示 / 存档，以 `↑`/`↓`/`?` 角标提示
- 丢帧检测与累计（`SampleFrame::droppedFrames`）→ 技术报警
- 单调时钟时基（`monotonicMs`）：告警计时不受 NTP 校时影响
- 技术报警通道（`AlarmEvent::Category::Technical`）与生理报警分离

### 新增 — 审计与持久化
- 审计追踪模块 `AuditLogger`：配置变更（旧值 → 新值）、告警事件、越权操作落盘
- 行内 CRC32 + `verifyFile()` 读回校验；界面新增「校验审计」按钮
- ISO 8601 带时区时间戳
- 历史文件格式 v2（新增 `monotonicMs / quality / invalid / artifact`），兼容 v1

### 新增 — 网络安全
- `FileIntegrity`：导出时生成 SHA-256 伴生清单 `<file>.sha256`，导入时校验
- 导入完整性阻断：清单存在但哈希不符 → 拒绝导入
- 导入输入校验：拒绝目录 / 空文件 / >256 MB / 含 NUL 字节的畸形文件
- 导出文件名净化（防路径穿越）
- `UserRole` 三级权限（查看者 / 操作者 / 管理员）+ 业务层二次校验 + 越权留痕

### 新增 — 可靠性
- 开机自检（`SelfTest`）：配置完整性 / 环形缓冲 / 文件系统可写性，结论显示在状态栏并写审计
- 历史文件按行容错解析（`HistoryRecorder::LoadStats`）：坏行跳过 + 明确上报
- 采集心跳（`VitalSignSimulator::heartbeat`）+ 看门狗（约 4 s 无推进 → 技术报警）

### 新增 — 界面
- `PatientBarWidget`：床号 / 患者 ID / 姓名 / 患者类型 + 角色切换 + 自检结论 + 报警计数
- 常驻「⚠ 演示模式 · 模拟数据」高对比标识
- 单位与量纲校验（`ChannelConfig::validateUnit`），配置面板标 ⚠ + 二次确认时列出
- 配置修改二次确认：弹出「旧值 → 新值」清单
- 配置锁定开关（防床旁误触）
- 每通道独立 Y 轴刻度（左右分列）

### 新增 — 测试
- `alarm_state_test`：8 → **11 个用例**（新增伪迹门控、单调时钟、确认时基）
- `compliance_test`（新）：**6 个用例 / 35 项断言**
  （哈希清单、导入校验、权限模型、文件容错、单位校验、开机自检）
- `ctest` 注册两个测试目标

### 新增 — 过程文档（`docs/`）
- `软件安全分级声明.md`（IEC 62304，工程上按 C 级、法律上非医疗器械）
- `SOUP清单.md`（8 项 SOUP + 4 条风险）
- `需求追溯矩阵.md`（45 条需求 ↔ 代码 ↔ 测试）
- `危害分析与FMEA.md`（12 条危害，含残余风险）
- `SBOM与网络安全.md`（SBOM + 10 条控制措施 + 8 项差距）
- `可用性工程文件.md`（IEC 62366-1 过程骨架 + 自查表）
- `变更控制流程.md`（分级、6 步流程、15 项回归清单）
- `CHANGELOG.md`（本文）

### 修复
- **关键**：告警「只报一次」锁存缺陷（可导致危重患者持续恶化而无人知晓）
- **关键**：系统校时回拨导致告警计时失效
- 单位校验中 `QLatin1String("℃")` 只取低字节导致「℃」被判为未登记单位
- 单位校验中 `Qt::CaseInsensitive` 引发的 Unicode 兼容字符折叠
  （`℃` ↔ `C`、`℉` ↔ `F` 互相匹配）
- `HistoryRecorder::loadFrames` 在坏行时静默跳过且不上报

### 变更（不兼容）
- 历史文件默认写出 v2 格式（加载端仍兼容 v1）
- 清空历史数据新增二次确认
- 导入数据不再复用 `onClearClicked()`（避免二次确认打断回放流程）

### 已知问题
- 无 GUI 自动化测试；界面相关的 15 条需求仅靠人工目视验证
- 采集卡死后只报警，不自动重启采集线程；数值未做「过期灰显」
- 极端越限值可能压扁趋势曲线（缺少绘图层 Y 轴截断）
- 无真实身份认证（切换角色仅审计，不阻断）
