## 2. 已实现的网络安全控制措施

| # | 控制措施 | 实现 | 对应需求 |
|---|---------|------|---------|
| N-1 | **导出文件哈希校验**：导出时生成 `<file>.sha256`，导入时校验 | `FileIntegrity::writeManifest()` / `verify()` | REQ-SEC-01 |
| N-2 | **导入完整性阻断**：清单存在但哈希不符 → **拒绝导入**（而非警告后继续） | `MainWindow::onImportClicked()` | REQ-SEC-01 |
| N-3 | **无清单时的显式降级**：允许导入旧文件，但在界面与审计中标注「未校验」 | 同上 | REQ-SEC-01 |
| N-4 | **输入校验**：拒绝目录、空文件、>256 MB、含 NUL 字节的畸形文件 | `FileIntegrity::validateImportFile()` | REQ-SEC-03 |
| N-5 | **路径穿越防护**：导出默认文件名净化，拒绝 `.` / `..` | `FileIntegrity::sanitizeFileName()` | REQ-SEC-03 |
| N-6 | **权限分级**：查看者 / 操作者 / 管理员，业务层二次校验 | `UserRole`、`MainWindow::ensurePermission()` | REQ-SEC-02 |
| N-7 | **越权留痕**：被拒绝的操作写入审计日志（含角色与所需权限） | 同上 | REQ-AUD-05 |
| N-8 | **审计日志完整性**：行内 CRC32 + 读回校验 | `AuditLogger::verifyFile()` | REQ-AUD-03 |
| N-9 | **恒定时间哈希比较**：避免逐字符提前返回 | `FileIntegrity::constantTimeEquals()`（内部） | — |
| N-10 | **最小权限的文件操作**：只读写用户显式选择的路径 | `QFileDialog` 全路径 | — |

### 2.1 控制措施的能力边界（必须说明）

| 能力 | 能防 | 不能防 |
|------|------|--------|
| SHA-256 伴生清单 | 意外损坏、传输截断、随手改一个数字 | **有意篡改且重算哈希**（攻击者可以同时改数据与清单） |
| CRC32 审计校验 | 意外损坏、单行改动 | 有意重算 CRC 的整行伪造 |
| 角色权限 | 误操作、无意识越权 | 有意切换角色的内部人（无口令认证） |

> 生产级方案需要：**HMAC + 密钥管理**（或只写一次存储 WORM）、
> **真实身份认证**（工牌 / AD / 双因素）、**传输加密**（TLS 1.2+）。
> 本项目**没有**这些能力，也不假装拥有。

## 3. 漏洞跟踪流程

### 3.1 定期扫描（建议流程）

```text
1. 每次发布前：在 NVD / GitHub Advisory 检索清单内所有组件
   - Qt 6.2.4 已进入 LTS 尾期，优先关注 Qt Security Advisories
   - MinGW / libstdc++ 关注 GCC 安全公告
2. 记录结果到 §3.3 表格（即使「无新增漏洞」也要记录扫描日期）
3. 评估 CVSS 与是否影响本项目实际使用的模块
4. 需修复 → 走 docs/变更控制流程.md 的变更请求
```

**检索入口**：
- NVD 关键词检索：`https://nvd.nist.gov/vuln/search/results?query=Qt+6.2`
- Qt 安全公告：`https://www.qt.io/blog/security-advisories`
- GCC 安全：`https://gcc.gnu.org/security/`

### 3.2 漏洞严重度处置时限（建议）

| CVSS | 处置时限 | 动作 |
|------|---------|------|
| ≥ 9.0 | 24 小时内评估 | 若不可修复则暂停发布 |
| 7.0 ~ 8.9 | 7 天 | 修复或书面接受风险 |
| 4.0 ~ 6.9 | 30 天 | 纳入下个版本 |
| < 4.0 | 下一次例行发布 | 记录 |
