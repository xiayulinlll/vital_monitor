### 1.2 工程优点（应保持）

在指出差距之前，先明确本项目**已经做对、且符合专业工程实践**的部分：

- **四层解耦架构**：数据采集 / 业务数据 / 绘图 / UI 层次清晰，便于测试与替换。
- **线程模型正确**：采集对象 `moveToThread()`，仅通过 `QueuedConnection` 信号槽通信，采集线程绝不触碰 UI 对象；自定义类型已通过 `qRegisterMetaType` 注册。
- **内存可控**：`RingBuffer` 定长 + `QReadWriteLock` 保护，支持长时间运行，内存上限恒定。
- **绘制性能优化**：静态网格背景预渲染缓存 + 局部重绘 + 批量提交，交互时不扰动原始数据。
- **坐标映射分离**：`CoordinateMapper` 独立维护各通道 Y 轴量程，绘图不参与业务计算。

### 2.2 ⚠️ 关键逻辑缺陷：告警"只报一次"

**位置**：`src/core/AlarmDetector.cpp` 第 31–54 行

```cpp
// ---- 上限判断 ----
if (cfg.hasHighAlarm && s.value > cfg.alarmHigh) {
    ++st.highCount;
    if (st.highCount >= m_debounceFrames && !st.highLatched) {  // 锁存后不再上报
        /* ... 生成一次 AlarmEvent ... */
        st.highLatched = true;
    }
} else {
    st.highCount = 0;
    st.highLatched = false;   // 只有回落到阈值内才解锁
}
```

**问题**：`highLatched` 一旦置位，**只有数值回落到阈值内才会解锁**。这意味着：

> 若患者心率持续 180 居高不下，**临床医护只会收到一次报警**，此后不再有任何提醒。

真实监护仪的报警必须是**持续性/周期性**的，直到被**确认（acknowledge）**或**报警条件解除**。这是本项目中最接近"临床危险"的一个点，建议优先修复。

> ✅ **已修复**：该锁存逻辑已整体移除，改为状态机 + `alarmRepeatMs` 周期重报。
> 回归守护：`tests/alarm_state_test.cpp` 用例 1（持续越限反复上报）、
> 用例 2（确认后仍按周期重报）、用例 3（超时未确认升级）。

> **能力边界（诚实声明）**：CRC32 能检出**意外损坏**与**随手改一个数字**，
> 但**不能**防住「有意重算 CRC 后整行伪造」。生产级需要 HMAC + 密钥管理
> 或只写一次存储（WORM），本项目不具备密钥体系，因此不做虚假承诺。

### 12.2 尚未真正完成的关键项（诚实清单）

| 项 | 为什么没完成 | 影响 |
|----|-------------|------|
| **临床验证**（阈值、伪迹阈值、SQI 门限） | 需临床专家与真实患者数据 | 阈值仅为工程取值，不能用于临床 |
| **可用性测试**（IEC 62366-1 形成性 / 总结性） | 需 ≥5–15 名真实医护参与 | 无法证明界面「好用」，仅能证明「做了」 |
| **集成 / 系统测试** | 需真实硬件链路与 7×24 稳定性测试 | 只能验证业务算法，不能验证整机 |
| **真实身份认证** | 无账号 / 证书体系 | 权限模型可被角色切换绕过（已审计留痕） |
| **自动化 SCA / CI** | 无流水线环境 | 漏洞依赖人工检索 |
| **历史数据定时落盘** | 断电一致性属架构级改造 | 断电仍会丢失未导出数据（已手动导出 + 清单兜底） |
| **采集线程自动恢复** | 需设计重启后的状态一致性 | 看门狗只报警，不自动恢复 |
| **绘制层 Y 轴截断** | 属视觉优化，未影响安全 | 极端值可能压扁曲线（数值本身仍正确显示） |

## 附：一句话总结

> 本项目的**工程架构（四层解耦、线程安全、环形缓冲、趋势图控件）干净且专业**，作为上位机 Demo 质量较高。但从医疗器械角度看，最大的短板不在架构，而在三处：
>
> 1. **报警系统**不满足 IEC 60601-1-8（无声音、无技术报警，且存在"只报一次"的潜在临床风险）；
> 2. **审计追踪与事件持久化**缺失；
> 3. **缺少软件生命周期与风险管理的过程文件**（决定它能否被称为"医疗器械"）。

> 📌 **上述三处短板的当前状态（v1.1.0）**：
> 1. 报警系统 → ✅ 三级优先级 / 状态机 / 分级声光 / 技术报警 / 限时暂停 / 报警列表均已实现，
>    「只报一次」缺陷已修复并由 `alarm_state_test` 用例 1–3 守护；
> 2. 审计追踪 → ✅ `AuditLogger` 落盘 + CRC32 读回校验；
> 3. 过程文件 → ✅ 7 份过程文件已建立（**工程自查级别，非法规符合性认定**）。
>
> 仍未闭合的是需要外部条件的事项（临床验证、真实用户可用性测试、
> 集成 / 系统测试、真实身份认证、自动化 SCA），清单见第十二章。
