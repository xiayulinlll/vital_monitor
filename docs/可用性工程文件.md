# 可用性工程文件（IEC 62366-1）

> 对应 `docs/医疗器材合规优化方向.md` **第六章**、**第三梯队第 17 项**。
>
> 本文按 IEC 62366-1 的**过程骨架**组织：使用场景 → 用户画像 → 任务分析 →
> 危险相关使用场景 → 界面设计对策 → 验证（目视检查表）→ 未开展的工作。
>
> ⚠️ **关键限制**：本项目**未开展任何医护人员参与的可用性测试**
> （形成性评价 / 总结性评价均无）。下文 §7 的检查表是**工程师自查**，
> 不能替代真实用户评价。

---

## 1. 预期用途与使用环境

| 项 | 内容 |
|----|------|
| 预期用途 | 多参数生理信号（HR / SpO₂ / RR / Temp）的趋势显示与报警提示 |
| 当前实际定位 | **演示程序**，数据来自模拟器，不可用于临床 |
| 使用环境（设计假设） | 床旁 / 护士站，中距离（1~3 m）观看，环境光较强，可能有噪声 |
| 使用时长 | 长时间连续（假设 7×24 h 运行） |
| 关键约束 | 报警必须在 1 m 外可辨识；操作应在少量点击内完成 |

## 2. 用户画像

| 用户 | 目标 | 主要风险 |
|------|------|---------|
| **值班护士** | 一眼确认患者稳定；快速响应报警 | 被误报淹没 → 忽略真报警（报警疲劳） |
| **临床医生** | 查看趋势、复核报警设置 | 误改报警限而无感知 |
| **设备科工程师** | 维护、导出数据、验证日志 | 误清空历史数据 |
| （演示场景）**评审者** | 快速理解架构与设计取舍 | 误把模拟数据当真实测量 |

## 3. 任务分析（关键任务）

| 任务 | 频率 | 步骤 | 失败后果 |
|------|------|------|---------|
| T-1 启动并确认设备可用 | 每次使用 | 启动 → 读自检结论 | 带故障运行 |
| T-2 识别当前患者 | 高频 | 看患者信息条 | 处置错患者 |
| T-3 发现并响应报警 | 高频 | 看到/听到报警 → 读报警列表 → 到床旁 → 确认 | 延误处置 |
| T-4 暂停报警以做护理操作 | 中频 | 点「暂停」→ 操作 → 到期自动恢复 | 忘记恢复 → 报警长期被抑制 |
| T-5 调整报警限 | 低频 | 切管理员 → 改数值 → 应用 → 二次确认 | 误改导致漏报 |
| T-6 复查历史数据 | 低频 | 导出 → 导入回放 → 读曲线 | 依据错误数据下结论 |

## 4. 危险相关使用场景（Use Scenarios）

| 编号 | 场景 | 危害 | 设计对策 | 对应危害分析 |
|------|------|------|---------|-------------|
| US-1 | 护士背对屏幕去处理另一位患者，此时报警响起但只响一次 | 漏掉持续恶化的报警 | 持续重复提示 + 超时升级 + 报警列表常驻 | H-1 |
| US-2 | 翻身导致电极脱落，数值看起来「正常」 | 未察觉信号失效 | SQI + invalid 标记 → 技术报警 + 显示 `--` | H-2 |
| US-3 | 患者活动造成单帧跳变 250 bpm | 误报警 → 报警疲劳 | 伪迹标记 → 抑制生理报警 + 技术提示 | H-3 |
| US-4 | 护士为换药暂停报警，随后忘记 | 报警长期被抑制 | 暂停有上限（危急 30 s / 普通 120 s）+ 倒计时可见 + 自动恢复 | H-6 |
| US-5 | 新护士不清楚当前限值，随手调大高限 | 漏报心动过速 | 需管理员 + 「旧值 → 新值」二次确认 + 审计 | H-8 |
| US-6 | 系统时间被自动校时回拨 | 报警计时失效 | 单调时钟计时 | H-5 |
| US-7 | 评审者看到「72 bpm」以为是真实测量 | 误导 | 常驻「演示模式 · 模拟数据」橙色标识 | H-12 |

## 5. 界面设计对策（已实现）

| 设计原则 | 具体实现 |
|---------|---------|
| **报警可见性** | `AlarmBanner` 顶部横幅：按优先级变色 + 闪烁；高优先级加白框；暂停时斜纹灰底 + 剩余秒数 |
| **报警可听性** | 分级提示音（危急 3 连响 / 900 ms，普通 1 响 / 1800 ms，提示 1 响 / 3000 ms） |
| **状态常驻** | 患者信息条显示「活动报警 N / 已确认 M」，未确认时红色 |
| **上下文完整** | 床号 / 患者 ID / 姓名 / 患者类型常驻可见 |
| **防误操作** | 配置锁定开关；改配置需管理员；二次确认；清空需确认 |
| **不掩盖异常** | 超量程显示 `↑`/`↓`，伪迹显示 `?`，不做 clamp |
| **可辨识性** | 每通道独立 Y 轴（左右分列、按通道配色、轴顶标缩写） |
| **诚实呈现** | 顶部橙色「演示模式 · 模拟数据」标识 + 启动日志声明 |

## 6. 色码与视觉规范（IEC 60601-1-8）

| 优先级 | 颜色 | 代码 | 闪烁周期 | 声音节奏 |
|--------|------|------|---------|---------|
| 高（危及生命） | 红 | `#D32F2F` | 300 ms | 900 ms / 3 连响 |
| 中（一般告警） | 琥珀 | `#D69A09` | 550 ms | 1800 ms / 1 响 |
| 低（提示） | 青 | `#2A9EB0` | 900 ms | 3000 ms / 1 响 |

> 全部颜色由 `SampleData.h` 的 `alarmIndicatorColor()` **单一来源**提供，
> 避免「曲线标记与横幅颜色不一致 → 被当成两个事件」。

**色盲友好性**：除颜色外，另用**文字（优先级名）+ 闪烁频率 + 声音节奏**三重编码，
不只依赖色相，因此红绿色盲用户仍可区分。

## 8. 未开展的工作（IEC 62366-1 差距）

1. **未编制可用性工程计划**（Usability Engineering Plan）。
2. **未开展形成性评价**（Formative Evaluation）：应在设计早期用低保真原型
   找 ≥5 名护士做任务走查。
3. **未开展总结性评价**（Summative Evaluation）：应在真实环境用
   ≥15 名代表性用户完成危险相关任务，记录**使用错误**与**任务成功时间**。
4. **无使用错误报告收集机制**（生产后信息）。
5. **无字体 / 对比度实测**（需照度计与色度计）。

> 结论：本项目**具备可用性设计意识与部分对策**，但**不满足 IEC 62366-1 的过程要求**。
