# 需求追溯矩阵（IEC 62304 §5.7 / 第三梯队第 13 项）

> 对应 `docs/医疗器材合规优化方向.md` **第五章「需求追溯矩阵」**、**第三梯队第 13 项**。
>
> 目的：回答「这条需求由哪段代码实现、由哪个测试验证」——
> 反向也能回答「这行代码为哪条需求存在」。
>
> 需求编号规则：`REQ-<来源>-<序号>`
> 来源：`ALM`=报警、`DATA`=数据完整性、`AUD`=审计、`SEC`=网络安全、
> `UI`=界面呈现、`REL`=可靠性、`PROC`=过程文档。
>
> **状态图例**：✅ 代码+测试均完成 ｜ 🟡 代码完成、无自动化测试 ｜ 📄 仅文档

---

## 1. 报警系统（IEC 60601-1-8）

| 需求编号 | 需求描述 | 设计 / 实现 | 验证 | 状态 |
|---------|---------|------------|------|------|
| REQ-ALM-01 | 报警须按临床优先级分高 / 中 / 低三级，不得由「超出阈值多少」折算 | `AlarmPriority`（`ChannelConfig.h`）、`AlarmDetector::levelForPriority()` | `alarm_state_test` 用例 8 | ✅ |
| REQ-ALM-02 | 须区分生理报警与技术报警两个独立通道 | `AlarmEvent::Category`、`AlarmDetector::detect()` | `alarm_state_test` 用例 6、7、9 | ✅ |
| REQ-ALM-03 | 报警条件持续成立时必须周期性重复提示，不得只报一次 | `AlarmDetector::updateCondition()`（`alarmRepeatMs`） | `alarm_state_test` 用例 1 | ✅ |
| REQ-ALM-04 | 须支持确认（acknowledge），确认后条件仍成立须重新提示；确认须幂等（连点不得重复留痕） | `AlarmDetector::acknowledge()` | `alarm_state_test` 用例 2、11、12 | ✅ |
| REQ-ALM-05 | 超时未确认须自动升级严重度 | `alarmEscalateMs` + `AlarmEvent::Escalated` | `alarm_state_test` 用例 3 | ✅ |
| REQ-ALM-06 | 报警延时须以毫秒定义，且采样率变化时行为一致 | `ChannelConfig::alarmDelayMs` | `alarm_state_test` 用例 4 | ✅ |
| REQ-ALM-07 | 报警限须随患者类型（成人 / 小儿 / 新生儿）切换 | `ChannelConfigManager::loadProfile()` | 目视验证 | 🟡 |
| REQ-ALM-08 | 须提供静音、暂停，暂停须有时长上限、到期自动恢复、状态可见 | `AlarmBanner::startPause()`（危急 30 s / 普通 120 s） | 目视验证 | 🟡 |
| REQ-ALM-09 | 须提供听觉 + 视觉双通道报警，且按优先级分级 | `AlarmBanner`（闪烁节奏 + 提示音节奏） | 目视验证 | 🟡 |
| REQ-ALM-10 | 报警颜色须符合 IEC 60601-1-8 色码 | `alarmIndicatorColor()`（`SampleData.h`） | 全控件共用同一函数 | ✅ |
| REQ-ALM-11 | 报警计时须使用单调时钟，不受系统校时影响 | `SampleFrame::monotonicMs`、`AlarmDetector::frameTimeMs()` | `alarm_state_test` 用例 10 | ✅ |
| REQ-ALM-12 | 须提供活动报警列表，按优先级 + 持续时间排序，显示确认状态 | `AlarmBanner::refreshList()`、`AlarmEvent::trackKey` | `alarm_state_test` 用例 12、13（键与时长可查） | ✅ |
| REQ-ALM-13 | 采集链路停滞须被检出并提示 | `VitalSignSimulator::heartbeat()`、`MainWindow::onWatchdogTick()` | 无 | 🟡 |

> **诚实说明**：🟡 的 15 条几乎全部是 **GUI 行为**。本项目未引入 Qt Test 的
> `QTest::mouseClick` 等 GUI 自动化手段，因此这些需求的「验证」实际依赖人工目视。
